# Viva preparation — Member 3 (evaluation, experiments, analysis)

Concepts in the order of the plan's study list, each with the one-line answer an examiner wants and the
follow-up they usually ask.

## 1. Training loss vs validation loss
*Training loss* is measured on the batches the optimiser is updating on; *validation loss* on held-out
text the model never trains on. Val ≈ train → the model generalises; val rising while train keeps falling
→ overfitting (memorising). Both flat and high → under-fitting / not learning (check LR, data, masking).
*Follow-up:* "Why not pick the checkpoint by test loss?" — then the test set is no longer an unbiased
estimate; selection uses validation, the test split is touched once.

## 2. Negative log-likelihood and perplexity
For each position the model gives a probability to the true next token; NLL = −log p(true token),
averaged over all tokens (nats/token, natural log). Cross-entropy loss *is* this NLL.
Perplexity = exp(mean NLL): the size of a uniform choice the model is "as confused as".
A model guessing uniformly over V = 8000 tokens has NLL = ln 8000 = 8.99 and perplexity 8000 — our
reference point. *Follow-ups:* lower is better; only comparable with the same tokenizer and evaluation
text (a tokenizer with longer tokens changes per-token perplexity); we average over tokens, not over
sequences, so long and short stories count per token.

## 3. Instruction-following evaluation
Perplexity measures predicting text, not obeying instructions. So E2 uses (a) response-only NLL on held-out
Dolly — how likely the model finds the human answer *given* the prompt; (b) generations on 60 fixed
held-out prompts with identical greedy decoding; (c) a blind 0–2 rubric on relevance, format,
answering-vs-echoing, coherence. *Follow-up:* "why blind?" — so we don't score our own fine-tuned model
more kindly.

## 4. Quantitative vs qualitative evaluation
Quantitative: numbers computed by a script (perplexity, NLL, tokens/s, repetition rate). Qualitative:
human judgement of real outputs (rubric, example generations, failure tags). We need both: numbers can
improve while outputs stay useless (e.g. lower NLL but still looping).

## 5. Training throughput and tokens per second
tokens/s = batch × sequence length ÷ time per optimisation step (forward + backward + AdamW), median of
steps after warm-up. Warm-up is discarded because the first steps include CUDA kernel compilation and
memory allocation. GPU work is asynchronous, so we call `torch.cuda.synchronize()` before reading the clock.

## 6. Inference latency and GPU memory
Forward latency: time for one forward pass of a [16, T] batch, swept over T = 128…2048. Generation
latency: ms per new token with our shared greedy loop. Peak memory: `torch.cuda.max_memory_allocated`
after resetting the counter. Softmax attention builds a T × T score matrix per head → time and memory
grow ~T²; linear attention replaces softmax(QKᵀ)V by φ(Q)(φ(K)ᵀV), cost ~T·d², so it only wins once T is
large relative to the head dimension d — at T = 256 it may well be slower, and that is a valid result.
*Follow-up:* a naive causal implementation (cumulative sum of φ(k)vᵀ for every position) stores a d × d
matrix per token, so its memory can be *worse*; efficient versions use chunking or custom kernels.

## 7. Controlled experiments and fair comparisons
Change one thing. The two attention variants share tokenizer, data split, model sizes, optimiser, LR
schedule, batch size, token budget, seed, GPU and PyTorch version (configs differ only in `attention`).
Speed is measured on the same GPU in the same session. Anything that could not be kept equal is written
next to the result.

## 8. Ablation studies and failure analysis
Ablation: remove/replace one component and measure the effect (here: softmax → linear attention; and
pre-trained vs + SFT). Failure analysis: tag bad outputs (echo, loop, story-mode, off-topic, truncated,
factual error), count them per model, show real examples, give a plausible cause (e.g. story-mode because
pre-training data is only children's stories).

## 9. Reproducibility, plots and interpretation
Every run → a row in `experiments/experiment_log.csv` (config, seed, git commit, hardware, result file).
Figures are generated by `src/make_figures.py` from saved JSON/CSV — nothing typed by hand. One y-axis per
chart; log axes for the sequence-length sweep because the T² vs T difference is a slope on a log-log plot.

## 10. Scientific reporting and limitations
Report what was measured, including negative results; state sample sizes (one seed per config, 60 prompts,
one rater), hardware and noise; don't claim "improves" without a measured, larger-than-noise difference.

* At which sequence length (if any) is linear attention faster / lighter than softmax on our GPU? — On the T4,
